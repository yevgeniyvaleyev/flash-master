## Project

FlashMaster is a personal Android-only app (Expo SDK 58, Expo Router, TypeScript) that enforces daily work norms the same way its sibling app AlgoMaster ([yevgeniyvaleyev/algo-master](https://github.com/yevgeniyvaleyev/algo-master)) does. Despite the name it has no flashcards; the user uses their own flashcards app and other tools, and FlashMaster only tracks the work.

- **Topics.** The user creates topics such as «Испанский — 10 карт.» or «Книга — 20 стр.». Each topic has a unit, a daily **target** and a daily **minimum**. Units are logged by hand in the app.
- **Blocking.** Selected entertainment apps stay blocked until every active topic reaches its **minimum**. Before that, each unit logged earns some time through the adaptive budget.
- **Targets.** Reminders, alarms and the streak keep aiming for the **target**.
- No auth, no backend. The UI is in Russian.

The skeleton (native modules, budget, alarms, reminders, theme) was copied from AlgoMaster commit `c8489bf` and adapted. When changing shared mechanics, compare with AlgoMaster first.

- EAS project `@ujeen/flash-master` (its own `projectId`; never reuse AlgoMaster's). The folder is not a git repo, so build with `EAS_NO_VCS=1 npx eas-cli@latest build -p android --profile preview` (APK); `.easignore` decides what is uploaded.

## Architecture

### Data

Everything lives in SQLite. Write transactions go through `writeTransaction` (sets a busy timeout), never `withExclusiveTransactionAsync` directly. `src/db/client.ts` holds the schema and migrations via `PRAGMA user_version`; `src/db/repo.ts` holds every query.

| Table         | Contents                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| ------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `topics`      | `daily_target`, `unlock_min`, `minutes_per_unit`, `step`, `color` (hex; NULL = palette color by id, v2), `mode` (`count`, or `position` for book mode), `position_total`/`position_current`, `linked_package`, `paused`, `completed_at` (v3), `reset_at` (v4), `archived`. Deleting a topic only archives it, so its history stays. A completed topic (fully finished, e.g. a book) is out of the daily norm and the dashboard and is listed under «Завершённые» on the Темы tab; it can be reopened. A progress reset (`reset_at`) keeps every entry but makes the topic's statistics (`topicStats(…, sinceDay)`) and total count from the reset on; in book mode it also sets the starting page. |
| `entries`     | Logged units (`units` > 0, `position` in book mode). Undo deletes the row.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `topic_days`  | Per topic per app day: `target`, `minimum` and `paused` as they were that day, plus `done`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `day_results` | The day's totals with `min_met` (unlocked) and `target_met` (streak).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `kv`          | Settings.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |

`topic_days` and `day_results` are upserted by `syncBlocker` on every background sync. Statistics read them, so changing a target never rewrites past days.

### Backups (same as AlgoMaster)

- `src/logic/backup.ts` (pure, tested) is the file format: a JSON snapshot of every user table, `kv` settings included, tagged `app: 'flashmaster'`. AlgoMaster's files are rejected, and so are snapshots from a newer schema.
- `src/backup/backup.ts` does the file I/O with `expo-file-system`.
  - `runAutoBackup` runs once per app day, on startup and on return to the foreground. It always writes `flashmaster-YYYY-MM-DD.json` into the internal `backups/` folder (last 3). With «Автокопия в папку» on, it also writes into a SAF folder the user picked (last `autoBackupKeep`).
  - Export saves a copy into a picked folder.
  - Going to the background runs a WAL checkpoint, so Android Auto Backup gets a complete `.db`.
- Restore: `requestRestore` saves the current data as `before-restore.json` and writes `restore-pending.json`. On the next start `migrate` drops every table, runs the migrations, and inserts the backup's rows (only columns the current schema has; topics first because of the foreign keys). Errors are stored in kv `restoreError` and shown in Settings.
- The UI is `src/components/BackupSection.tsx` in Настройки → «Резервные копии».

### Daily norm (`src/logic/goal.ts`, pure, tested)

- `topicProgress` uses `minimum = min(unlockMin, dailyTarget)`.
- `dayProgress` sums the active topics (`isActive`: not paused, not completed, not archived):
  - `unlocked` means every minimum is met. It is also true when there are no active topics.
  - `targetMet` means every target is met. It is false when there are no active topics.
- `completionEvents` emits one event per logged unit up to the topic's minimum, with that topic's `minutesPerUnit` cost. These events feed the budget.

### Days

These are app days, not calendar days.

- `dayKey()` (`src/logic/dates.ts`) shifts the day by `dayStartHour`. The native blocker and alarms shift their `today()` the same way.
- Stored day keys are never recomputed.
- A streak (`computeStreak` and `bestStreak` in `src/logic/progress.ts`) skips neutral days (`null`: no active topic, or a paused topic). A day with no result breaks the streak.

### Reactivity

There is no query library.

- Mutations go through `src/logic/actions.ts`, which bumps `useDataVersion` and re-syncs the background immediately, so a logged unit can unlock apps at once.
- `useQuery(fn, key)` re-runs on screen focus and on every bump. Returning to the foreground also bumps.
- Call mutations from `actions`, never directly from `repo`.

### Background sync

`syncBackground` (`src/logic/background.ts`) loads `loadDayBudget` once and passes it to reminders, the blocker and alarms. It runs on startup, on return to the foreground, after mutations, and when any of the `BACKGROUND_SETTING_KEYS` change.

### App blocking (`modules/app-blocker`)

This is a Kotlin AccessibilityService copied from AlgoMaster.

- The native side only knows "tasks". `syncBlocker` sends `dailyGoal = Σ minimums` and `learnedToday = Σ min(done, minimum)`. The unchanged Kotlin `learned >= goal` check then unlocks everything once every minimum is met.
- Topics' `linkedPackage`s are removed from `blockedPackages` before `setConfig`.
- `launchApp(pkg)` opens a linked app.
- The module is `null` in Expo Go.

### Coexistence with AlgoMaster

Both apps may block the same app. That app then opens only when both apps allow it. Each service ends its session as soon as the other app's `BlockActivity` comes to the front, so no time is charged while blocked.

- `BlockerStore.PROTECTED_PACKAGES` (`io.flashmaster.app`, `io.algomaster.app`) are never blocked and are hidden from the picker.
- Keep every native identifier distinct from AlgoMaster's: package, scheme `flashmaster`, prefs `flashmaster_*`, `taskAffinity` `io.flashmaster.*`, the service label, and the Expo module names (`FlashMasterAppBlocker`, `FlashMasterStudyAlarms`). With the module names distinct, this JS bundle loaded into AlgoMaster's dev client finds no native modules instead of overwriting AlgoMaster's config.
- AlgoMaster does not yet have the matching protection for `io.flashmaster.app`.

### Adaptive budget

The maths is in `src/logic/budget.ts` (pure, tested). `loadDayBudget` in `src/logic/day-budget.ts` loads it.

- **Toward the minimums:**
  - each unit still needed reserves its topic's minutes;
  - each unit done grants `clamp(slack / (left + 1), 0, maxGrant)`, where `maxGrant` is the topic's `max_grant_minutes` (v5) or, when NULL, the global `maxGrantMinutes`.
- **Toward the targets:** `splitSessions` (`src/logic/sessions.ts`, pure, tested) splits each topic's work left into sessions of whole units, each at least `minSessionMinutes` long (setting; 0 = one block per topic). It places each topic's sessions at evenly spaced points (k + ½)/n of the day and interleaves topics by those points. `blocks` holds these sessions; `planDay` spaces them out and `dayTimeline` lays them out for the «План дня» card, each in its topic's color. After the unlock, the gaps between blocks are `unlimited`.
- **Topic colors:** `src/logic/topic-colors.ts`. A new topic gets the first unused palette color unless one is picked in the form.

### Study alarms (`modules/study-alarms`)

- **Item fields:** `slug` is the topic id, `title` is the topic name, and `difficulty` carries the units label «12 стр.». The native side appends the minutes.
- **Lists:** both are split into sessions by `splitSessions`, so one topic can have several alarms a day.
  - `upcoming` is today's work left;
  - `tomorrow` and `tomorrowGoal` are the full targets, planned for the next day or when the stored day is stale.
- **Behaviour:** alarms stop once every target is met. «Начать» deep-links to `flashmaster://topic/<id>`.
- **Keep in sync:** `StudyPlan.kt` mirrors `planDay`/`nextAlarmAt` in `src/logic/study-plan.ts`.

### Reminders

`src/notifications/reminders.ts` and `reminderText` in `src/logic/reminders.ts`. Today's text first lists the work left to unlock, then the work left to the targets.

### Book mode (`src/logic/position.ts`)

- The user enters the page reached; the difference from `position_current` is logged.
- Deleting such an entry moves the current page back by its units.

### Statistics

`src/logic/stats.ts`: `topicStats` (window total, average over tracked days, target-met rate, streaks) and `dayGrade` (`target`, `minimum`, `missed` or `none`).

### Navigation

expo-router ships its own fork of react-navigation, so don't install `@react-navigation/*`.

- Tabs in `src/app/(tabs)`: Сегодня (summary, horizontal per-topic bars `TopicBars` in one column (full name above each bar, minimum line), logging rows, day plan; the badge shows units left to unlock), Темы, Статистика, Настройки.
- Stack screens: `topic/[id]` (log, entries, book, statistics), `topic/edit` (create, or edit with `?id=`), `blocked-apps`.
- Logging buttons live in `src/components/LogControls.tsx`.
